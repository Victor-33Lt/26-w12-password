# 비밀번호 보안 도구 (`26-w12-password`)

> **CyberSec Password Shield**는 안전한 비밀번호 생활을 위한 **올인원 비밀번호 보안 도구 웹앱**입니다.  
> 브라우저 내장 Web Crypto API를 활용한 실시간 강도 검사 및 암호학적 난수(CSPRNG) 생성, Have I Been Pwned API를 활용한 **k-익명성(k-Anonymity) 기반 유출 확인**, 그리고 **PBKDF2 + AES-256-GCM 기반 영지식(Zero-Knowledge) 암호화 금고**를 제공합니다.

---

## 소개

본 프로젝트는 사이버보안 관점에서 **"비밀번호를 외부 서버에 넘기지 않고도 어떻게 보안성을 점검하고 침해 사고 여부를 확인할 수 있는가?"**에 대한 해답을 제시하는 보안 대시보드 웹앱입니다.

- **🛡️ 실시간 비밀번호 강도 검사기**:
  - 비밀번호 입력 시 외부 네트워크 전송 없이 100% 브라우저 메모리 내부에서 실시간으로 강도, 정보 엔트로피(Bits), 브루트포스 크래킹 예상 시간을 산출합니다.
  - 단순 길이뿐만 아니라 문자 다양성, 연속 키보드 배열(`qwer`, `1234`), 반복 문자(`aaa`), 흔한 취약 단어(`password`, `admin`)를 종합 진단합니다.
- **⚡ 암호학적 난수(CSPRNG) 비밀번호 생성기**:
  - 보안 취약성이 있는 `Math.random()`을 배제하고 `window.crypto.getRandomValues()`를 사용하여 예측 불가능한 강력한 비밀번호를 생성합니다.
  - 길이(6~48자), 문자 집합(대/소문자, 숫자, 특수문자), 가독성을 위한 혼동 문자(`l, 1, I, O, 0`) 제외 옵션 및 원클릭 복사를 지원합니다.
- **🔍 k-익명성 기반 유출 확인 (Have I Been Pwned)**:
  - 비밀번호 원문이나 전체 해시를 절대 전송하지 않고, SHA-1 해시의 **앞 5글자(Prefix)만** 전송하는 **최소 전송 원칙(k-Anonymity)**을 구현했습니다.
  - 서버로부터 받은 수백~수천 개의 접미사 목록과 내 해시의 뒤 35글자(Suffix)를 **브라우저 내부에서 대문자 기준으로 대조**하여 안전하게 유출 횟수를 확인합니다.
- **🔐 영지식(Zero-Knowledge) AES-256-GCM 암호화 금고**:
  - 마스터 비밀번호로부터 PBKDF2(100,000회 반복)를 통해 키를 파생하고, 중요 메모를 AES-256-GCM으로 암호화·복호화하는 E2EE(종단간 암호화) 환경을 제공합니다.
- **📡 네트워크 전송 투명성 모니터 (Network Transparency Inspector)**:
  - 개발자 도구(F12)의 Network 탭과 동일하게 실제로 어떤 데이터가 외부로 전송되는지(원문: 0 bytes, 해시: 앞 5글자만 5 bytes)를 눈으로 확인할 수 있는 감사 인스펙터를 제공합니다.

## 나의 AI 기획·구현 과정

### 1. AI 협업 방식
- **Antigravity IDE & Gemini 종합 워크플로우**:
  - 프로젝트 기획 단계에서 사이버보안과의 눈높이에 맞추어 "강도 검사 + 생성기 + 유출 확인 + 암호화 금고"라는 올인원 아키텍처를 수립했습니다.
  - 암호학적 핵심 로직(`src/utils/crypto.js`)을 UI 컴포넌트와 철저히 분리하여 설계하고, Node.js 환경에서 Web Crypto API 공식 해시 벡터 및 CSPRNG 난수 품질, AES-GCM 암/복호화 무결성 테스트를 사전에 통과시킨 뒤 UI를 결합했습니다.
  - Oxlint 정적 분석 도구를 주기적으로 실행하여 `Found 0 warnings and 0 errors`를 유지하며 무결점 코드를 완성했습니다.

### 2. 비밀번호 "강도"의 기준 정의
단순한 글자 수 체크를 넘어, 실제 무차별 대입(Brute-force) 공격과 사전(Dictionary) 공격에 저항할 수 있도록 다층적인 평가 기준을 수립했습니다:
1. **문자 집합 풀(Pool)과 정보 엔트로피(Bits) 계산**:
   - 대문자(26), 소문자(26), 숫자(10), 특수문자(32)의 사용 여부에 따라 총 문자 풀 크기 $N$을 계산하고, 섀넌 엔트로피 공식 $E = L \times \log_2(N)$을 통해 비밀번호의 수학적 무작위성을 정량화했습니다.
2. **사전 공격 및 휴리스틱 패턴 감지**:
   - 동일 문자 3회 이상 연속 반복 (`aaa`, `111` 등) 감지 시 감점
   - 연속된 키보드 및 알파벳 순서 (`qwer`, `asdf`, `1234`, `abcd` 등) 감지 시 감점
   - 널리 알려진 취약 단어 (`password`, `admin`, `welcome`, `qwerty`, `login` 등) 포함 시 감점
3. **현실적인 크래킹 소요 시간 추정**:
   - 초당 1,000억 회의 해시 연산이 가능한 오프라인 고성능 GPU 클러스터 공격자를 기준으로, 엔트로피 비트 수에 따른 현실적인 크래킹 소요 시간(순식간 ~ 우주 나이 이상)을 직관적으로 시각화했습니다.

### 3. 구현 중 가장 막혔던 문제와 해결 과정
- **문제: HIBP Range API 해시 대소문자 불일치로 인한 오탐지 위험**:
  - Have I Been Pwned Range API의 응답은 항상 **대문자(Uppercase)** 16진수 문자열로 반환됩니다.
  - 초기 구현 시 브라우저 Web Crypto API의 `crypto.subtle.digest` 변환 결과가 소문자로 유지된 상태에서 단순 문자열 비교를 수행할 경우, 이미 수천만 번 유출된 대표적인 비밀번호(`password`)조차 목록에서 일치하지 않아 "안전함(유출 기록 없음)"으로 오판하는 치명적인 보안 취약점이 발생할 수 있었습니다.
- **해결 방안**:
  - `calculateSha1()` 함수에서 해시 생성 즉시 `.toUpperCase()`로 정규화하도록 설계하고, API 응답 텍스트를 파싱하는 루프에서도 `lineSuffix.toUpperCase() === suffix`로 엄격하게 상호 대문자 대조를 수행하여 어떠한 상황에서도 유출 여부가 누락되지 않도록 완벽히 해결했습니다.

## 보안 점검 (사이버보안과 체크포인트)

### 1. 비밀번호 생성에 `Math.random()` 대신 `crypto.getRandomValues()`를 써야 하는 이유
- `Math.random()`은 암호학적으로 안전하지 않은 의사 난수 생성기(PRNG, 주로 xorshift128+ 알고리즘)입니다. 난수 생성 알고리즘의 내부 상태(State)가 단순하며 시드가 시간이나 카운터에 의존합니다. 공격자가 연속된 몇 개의 난수 출력값만 관측하면 내부 상태를 역추적하여 **이후에 생성될 비밀번호를 100% 예측**할 수 있습니다.
- 반면 `window.crypto.getRandomValues()`는 운영체제(OS) 커널 수준에서 하드웨어 인터럽트, I/O 지연 시간, 키보드/마우스 입력 노이즈 등 물리적 시스템 엔트로피 풀을 수집하여 시드를 공급하는 **CSPRNG (Cryptographically Secure Pseudo-Random Number Generator)**입니다. 과거의 모든 난수 값을 알고 있더라도 다음 난수의 비트를 수학적으로 예측할 수 없는 **다음 비트 예측 불가능성(Next-bit Unpredictability)**을 보장하므로 보안 자격증명 생성에 필수적입니다.
- 추가로 모듈로 편향(Modulo Bias)을 방지하기 위해 거부 샘플링(Rejection Sampling) 기법을 적용하여 완벽하게 균등한 확률 분포를 구현했습니다.

### 2. Network 탭에서 확인한 실제 요청 주소 검증
- **테스트한 비밀번호**: `password`
- **SHA-1 전체 해시**: `5BAA61E4C9B93F3F0682250B6CF8331B7EE68FD8`
- **Network 탭에서 확인한 실제 외부 요청 URL**:
  ```http
  GET https://api.pwnedpasswords.com/range/5BAA6
  ```
- **네트워크 전송 결과 분석**:
  - 비밀번호 원문(`password`)이나 전체 해시(40자리)는 절대 외부로 전송되지 않았습니다.
  - 외부 서버(Cloudflare/HIBP)로 전송된 데이터는 오직 앞 5글자(`5BAA6`)인 **5바이트**뿐입니다.
  - 서버는 5BAA6으로 시작하는 수백 개의 해시 접미사 목록(`1E4C9...:52256179`)을 반환했을 뿐이며, 사용자가 그중 어떤 비밀번호를 찾았는지는 전적으로 클라이언트(브라우저 메모리)에서만 비밀리에 판정되었습니다.

### 3. k-익명성 방식으로도 서버가 알 수 있는 정보 (완전한 익명이 아닌 이유)
k-익명성은 사용자의 비밀번호 원문과 특정 대상을 보호하지만, 네트워크 프로토콜의 특성상 서버는 여전히 다음 정보들을 관측할 수 있습니다:
1. **클라이언트의 공인 IP 주소**: 어느 네트워크/조직/지역에서 요청이 인입되었는지 식별 가능
2. **요청 발생 시각(Timestamp)**: 사용자가 언제 유출 여부를 조회했는지 활동 시간대 파악 가능
3. **해시의 앞 5글자 접두사(Prefix)**: 사용자의 비밀번호 해시가 `5BAA6` 범위(16진수 16^5 = 1,048,576개 버킷 중 하나)에 속한다는 메타데이터
4. **패킷 크기(Side-channel)**: 기본 설정 시 특정 prefix의 유출 해시 개수에 따라 응답 바이트 크기가 달라져 데이터 규모를 유추 가능 (본 프로젝트에서는 `Add-Padding: true`를 적용하여 가짜 더미 데이터를 섞어 패킷 크기 기반 사이드채널 공격을 방어함)

## 나만의 확장 기능

기본 4가지 필수 기준(강도 검사, CSPRNG 생성기, k-익명성 유출 확인, Network 탭 검증) 외에 보안성과 완성도를 극대화하기 위해 다음과 같은 고급 기능들을 추가 구현했습니다:

1. **`Add-Padding: true` 헤더 지원 및 지능형 필터링**:
   - Cloudflare 및 HIBP가 지원하는 패딩 헤더를 기본 활성화하여, 응답에 유출 횟수가 0인 더미(Dummy) 해시 항목을 무작위로 주입받습니다.
   - 이를 통해 네트워크 스니퍼가 응답 바이트 크기를 관측하여 특정 버킷의 유출 건수를 역산하는 트래픽 분석(Traffic Analysis) 공격을 차단하며, 브라우저 대조 시 `count > 0`인 항목만 정확히 판정합니다.
2. **PBKDF2 + AES-256-GCM 영지식(Zero-Knowledge) 암호화 금고 (Safe Vault)**:
   - 사용자가 입력한 마스터 비밀번호로부터 PBKDF2(SHA-256, 100,000회 반복, 16바이트 CSPRNG 솔트)를 통해 암호화 키를 파생합니다.
   - Web Crypto API의 `AES-GCM` 알고리즘과 12바이트 난수 IV를 사용하여 기밀성과 무결성(인증 태그)을 동시에 보장하는 종단간 암호화(E2EE) 금고를 제공합니다. 마스터 비밀번호를 분실하면 그 누구도 데이터를 복구할 수 없는 암호학적 원리를 직접 체험할 수 있습니다.
3. **네트워크 데이터 전송 투명성 인스펙터 (Network Transparency Monitor)**:
   - 개발자 도구를 열기 번거로운 사용자를 위해, 현재 브라우저 메모리에 있는 데이터(원문, 40자리 해시)와 외부로 나가는 데이터(5자리 Prefix, GET URL)를 실시간 비교 테이블 형태로 시각화하여 최소 전송 원칙을 한눈에 확인할 수 있도록 지원합니다.
4. **사이버보안 원리 인터랙티브 교육 패널**:
